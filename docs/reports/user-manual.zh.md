# ManiScope 用户手册

## ManiScope 是什么

ManiScope 是一个用于评估加密货币市场交易型价格操纵风险的可视化分析仪表板。系统的目标场景是去中心化交易所上的 memecoin 交易：这类市场进入门槛低、连续交易、监管有限，操纵者很容易通过多地址协调、短时间集中交易或制造虚假交易活动来影响市场信号。ManiScope 会加载一系列预先计算好的数据集，包括 DEX 成交日志、代币转账日志、按小时粒度的余额快照、以及每个用户的行为序列，针对 ACT 和 PNUT 这两枚 Solana 上发行的示例代币之一运行实体聚类、链接检测和操纵检测，再通过四个相互联动的可视化视图把结果呈现出来。

ManiScope 的定位是面向回溯调查的分析工具，而不是实时风控告警系统。它擅长回答“过去几周是谁在操纵这枚币、相关钱包是怎么连接起来的、它们的行为如何推动了价格”这类问题，而不是“此刻是否有可疑情况正在发生”。预期的使用方式是探索式的：先选定一个时间快照，配置检测规则，跨四个视图寻找可视模式，发现异常时再点击单个持有者深入下钻。

## 屏幕布局

仪表板会铺满整个浏览器窗口，分成左中右三列。左列是一条窄长的 Control Panel（控制面板）。中列上下分割为两块，上方是 Token Distribution View（代币分布视图），下方是 Behavior Detail View（行为细节视图）。右列是 Manipulation View（操纵视图），由一张 K 线图与上下两行细节卡片组成。

```
+----------------------------------------------------------------------+
|  ManiScope                                              o ACT  o PNUT |
+--------------+----------------------------+--------------------------+
|              | Token Distribution View    | Manipulation View        |
|              | (头部持有者环 +             | -- Round-Trip 卡片行 --   |
|              |  相关持有者外环)            | |   K 线 + 联动连接带 |  |
|  Control     |                            | -- Same-Direction 卡片行  |
|  Panel       +----------------------------+                          |
|              | Behavior Detail View       |                          |
|              | (选中持有者及其实体        |                          |
|              |  和相关持有者)             |                          |
+--------------+----------------------------+--------------------------+
```

## 四个视图的细节

### 1. Control Panel（左列控制面板）

Control Panel 是整个仪表板的驱动入口。它包含四组配置区，每组都有自己的执行按钮。

**Snapshot Configuration（快照配置）** 位于最上方。Snapshot Time 下拉菜单允许从 2024-10-19 12:00 UTC 起的任意整点中选取一个时间。仪表板里其他视图的所有结果都是相对于这个时间点计算出来的，因此切换它是你能做的影响最大的操作。两个阈值决定了最终落在屏幕上的持有者群体：**Top Holders Threshold**（默认 0.3）是希望覆盖的累计余额比例，0.3 意味着“能够覆盖大约 30% 总代币供应量的最小头部持有者集合”。第二个阈值用于识别**相关持有者**，也就是那些与至少一个头部持有者之间存在直接转账、且自身持有量不低于一个可配置最小值的地址。Related User Threshold（默认 0.2）的最小持有量并不是绝对数值，而是相对于最小的头部持有者余额而言的，因此在不同流动性水平的代币之间这个判断标准都能保持稳定。Update Snapshot 按钮会按当前时间重新计算并刷新 Token Distribution View。

**Entity Detection Configuration（实体检测配置）** 在第二个区块。橙色的 Run Detection 按钮会触发钱包聚类算法。规则可以从三个维度进行设定，与论文中规则表的设计保持一致：**network-based** 规则查询预先聚合好的转账网络统计；**similarity-based** 规则比较各个用户的时间序列；**manipulation-based** 规则在多个钱包共同参与同一种操纵模式时把它们聚到一起。network-based 规则包括 Direct Transfer（地址对之间存在双向转账）、Funding Relationship（两个地址是否拥有相同的首次资金来源）以及 Same Sender / Same Recipient 等开关。similarity-based 规则覆盖交易动作序列、余额序列和收益序列，每一种都对应自己的相似度阈值。

**Link Detection Configuration（链接检测配置）** 是第三个区块。它的执行按钮在运行中的应用里标注为 Update Links。它与 Entity Detection 共享同一套规则族，但故意采用更宽松的阈值。这种切分的核心思路是“严苛 vs 宽松”：实体检测使用硬聚类（基于满足规则的 Union-Find）和最严格的阈值，目的是把误报降到最低；链接检测则采用更柔和的两两关联和更宽松的阈值，目的是鼓励发现更多潜在线索。结果是实体检测会产出由橙色虚线圆圈包裹的钱包群组，而链接检测会产出可视化为持有者之间的灰色连线，作为一种暂定的关联关系展示在 Token Distribution View 里。

**Manipulation Detection Configuration（操纵检测配置）** 是第四个区块。它的 Run Detection 按钮触发交易模式检测器，提供两条互补的规则。Round Trip 规则寻找“买进然后再卖出”的子序列，要求交易者的净持仓回到接近零的水平、且收益微乎其微，这是洗盘行为的经典信号。Same Direction 规则寻找连续同向交易的延续段，期间不允许混入任何反向交易，这是协同建仓或协同出货的经典信号。两条规则都可以在开启 entity_based 开关后以**实体级别**运行：此时同一实体内所有钱包的交易会先合并、再交给规则检测，原本散落在多个钱包之间从而无法被单钱包检测发现的协同活动，也就因此变得可见。

有一个细节在 UI 上看不出来：页面首次加载时会自动运行所有检测算法，切换快照时间并点击 Update Snapshot 也会触发自动重跑。但是切换 ACT 与 PNUT 时操纵检测结果会被清空，必须手动再点一次 Run Detection 才能重新填充数据。

### 2. Token Distribution View（中列上方的代币分布视图）

Token Distribution View 是一种增强的节点-连边图，同时刻画头部持有者之间的持币分布与相互关系。它具有**双环结构**。

**内环**承载的是 Top Holders Threshold 选出的头部持有者。每个头部持有者用一个节点表示。节点尺寸编码绝对持币余额，圆圈越大代表持仓越多。节点填色使用蓝色渐变，颜色越深代表余额越高。所有持有者节点采用带有碰撞规避的力导向布局，避免视觉重叠；存在连边的节点会被布置得更紧凑，但仍然遵守“头部持有者必须落在内环之内”的空间约束。

**外环**承载的是相关持有者，也就是被阈值过滤掉但仍然与头部持有者之间有直接转账的地址。它们的节点尺寸与内环保持一致的标度，使得相关持有者与头部持有者之间的体量对比可以一眼看出。再外面一层在概念上是 Others 聚合节点，把所有既不属于头部、也与头部不相关的持有者整合在一起；它是否真正显示，取决于阈值设置和当前快照的具体分布。

下面这一组视觉编码叠加在这个布局之上。

- **节点的红色描边**：该钱包在当前规则下至少出现在一次被检出的操纵事件中。所有可疑钱包都会被这种红色描边高亮。
- **节点的蓝色描边**：当前这一轮的操纵检测没有把该钱包标记为可疑。
- **包裹一组内环节点的橙色虚线圆圈**：被检出的实体。被算法判定为属于同一实体的头部持有者会被空间上聚拢在这个虚线圆圈内。
- **从相关持有者到实体的橙色虚线连边**：相关持有者会被一条橙色虚线连边连接到对应的实体虚线圆圈上，表示该相关持有者属于该实体的转账邻域，但本身没有被聚类进实体之内。
- **两个持有者之间的灰色连边**：链接检测发现的关联关系。灰色连边是两两的，而非分组的，它捕捉的是那些没有强到构成实体规则、但仍然值得标注出来的关联关系。

视图上的交互很简单。**悬停**在任意节点上会弹出工具提示，显示钱包地址、持币余额；如果该钱包被标记为可疑，还会显示具体的标记原因。**点击**任意节点会选中对应的持有者，自动填充下方的 Behavior Detail View，并在视图中高亮该持有者所属的实体（如果它属于某个实体）。标题栏里的 Scale 滑块可以整体放大或缩小整个视图。

每次进入这个视图时第一眼应该看的，是红色与蓝色描边的比例。少数红色是任何活跃代币的正常状态。绝大多数都是红色则意味着头部持有者中存在大面积的操纵活动，这就是开始深入调查的信号。第二眼则要看橙色虚线圆圈的位置：每一个橙色圆圈都是实体检测器确认度较高的钱包群组，是点击下钻的天然起点。

### 3. Behavior Detail View（中列下方的行为细节视图）

Behavior Detail View 用于呈现与一个被选中持有者相关的所有持有者的详细行为。默认是空的，只有在你点击 Token Distribution View 中的某个节点之后才会被填充。

**纵轴**列出从中心向外的一组持有者：被选中的持有者位于中心，与之存在实体或链接关系的所有其他持有者环绕在它周围。**横轴**是时间。对于每个持有者，行为从**三个维度**展开呈现：actions（动作）、balance（余额）、earnings（收益）。

**Actions（动作）** 用沿时间线分布的彩色小圆点编码：蓝色圆点是买入，粉色圆点是卖出，灰色圆点是转账。每一个小圆点对应该持有者的一笔交易事件。

**Balance（余额）** 用蓝色面积图可视化整体持币余额随时间的变化。面积图之上叠加蓝色和粉色的条形，分别标注由买入或卖出动作引起的余额变化时刻，使你一眼就能看出哪一笔动作对余额产生了什么方向的影响。

**Earnings（收益）** 用动作标记下方的条形编码：红色条形代表已实现亏损，绿色条形代表已实现收益。这些条形累计反映了该持有者通过交易获得的实际盈亏。

控制面板（或视图自带的标题栏，取决于布局版本）上的 **Show Manipulation Boxes** 开关一旦打开，会在被检出为操纵行为的动作序列上叠加**红色包围框**。当你想精确看到检测器在哪些时间窗口里、哪些动作序列上做了标记时，把这个开关打开就行。

用户可以缩放视图，以放大查看感兴趣的特定时间段的行为细节。

把多个持有者的时间线堆叠在一起的核心目的是“可视化协同检测”。如果两个钱包由同一个人操控，它们的小点会在垂直方向上对齐，因为它们在同一时刻执行了同一动作；如果两个钱包真的彼此独立，它们的小点会在各行之间随机散布。当多个钱包同时下场操纵时，会形成一道纵向贯穿大多数行的密集小点带。这个视图最被低估的用途是它的“相关持有者”行：实体检测器只在余额几乎完全同步时才会把钱包聚到一起，因此那些虽然由同一操纵者控制、但充提币时间表不一致的钱包会被漏掉。相关持有者行通过转账图把这些被漏掉的钱包重新拉回来，常常能揭示出比实体边框暗示的范围大得多的网络。

### 4. Manipulation View（右列操纵视图）

Manipulation View 展示价格动态与被检出的操纵行为之间的时间关系。它围绕一张 K 线图，由若干层叠的组件纵向堆叠而成。

中间的 **K 线图**用用户选择的时间粒度可视化价格走势（运行中的应用提供 1H、1D、3D、1W 四档）。每根蜡烛在对应区间里编码 OHLC 四个价格，颜色表示这一区间内收盘价相对于开盘价是上涨（绿色）还是下跌（红色）。

K 线图**上下两侧**分别有一组**灰色柱状图**，按时间区间统计每种类型操纵模式的检出数量。上方的柱状图统计 Round-Trip 操纵，下方的柱状图统计 Same-Direction 操纵。两组柱状图加在一起，能让你一眼看出哪些区间里集中爆发了操纵活动。

被检出存在操纵行为的时间区间，还会在 K 线图本身上叠加一层**淡蓝色背景**，使价格走势与操纵标记共享同一条横轴。

除了柱状图，视图还以**位于 K 线图上下的小卡片**形式提供更详细的细节视图。每张卡片描述一段特定时间区间里被识别出来的具体交易模式。上方是 Round-Trip 卡片，下方是 Same-Direction 卡片，它们使用与 Behavior Detail View 相同的内部布局，只是尺寸更小：买入和卖出动作用蓝色和粉色圆点编码；纵轴列出参与这次操纵的所有钱包；横轴是与本次操纵相关的动作序列。卡片头部显示小时槽位、时间区间、本次事件的总美元金额，以及一个截断的钱包地址。

K 线图和卡片之间通过三层交互联动起来。第一，可以**缩放** K 线图以导航到特定的感兴趣时间段。第二，可以**独立滚动卡片行**，上下两行卡片各自配有水平滚动条，与 K 线图的缩放互不影响。第三，每张卡片始终与它对应的时间区间通过一条**淡蓝色连接带**保持视觉连接，因此即便你滚动了卡片或缩放了 K 线图，仍然可以追溯任何一张卡片到它所属的那一根蜡烛。

### 代币选择器

页面右上角有一对小型单选按钮，标签分别是 ACT 和 PNUT。在两者之间切换会更换整个仪表板的数据源。ACT 在默认快照下大约有 51 个活跃头部持有者，7 张 Round-Trip 卡片和 70 张 Same-Direction 卡片。PNUT 在默认快照下大约有 191 个活跃头部持有者，整个网络图明显更密。需要注意的是，切换代币会清空操纵检测结果，必须再次点击两个 Run Detection 按钮才能重新填充。

## 检测规则参考

下面列出运行中的应用所采用的默认参数，便于查阅。这些数值与论文中的规则表一致。

### Network-based 检测规则

| 规则 | 检测内容 | 关键参数 |
|---|---|---|
| Direct transfer | 一对地址之间是否存在双向互转 | min_tx_count（实体: 3, 链接: 1）, min_tx_volume |
| Funding relation | 两个地址是否拥有相同的首次资金来源 | 实体侧启用，链接侧禁用 |
| Same sender / recipient | 多个地址是否共享同一对手方 | 仅有开关 |

### Similarity-based 检测规则

| 规则 | 方法 | 关键参数 |
|---|---|---|
| Trading action seq. | 在交易事件上做连续子序列匹配 | type（实体: action+amt+price; 链接: action only）, max_time_diff（实体: 20 分钟; 链接: 120 分钟） |
| Balance seq. | 在重采样后的余额历史上计算 Pearson 相关性 | similarity_threshold（实体: 0.6, 链接: 0.7） |
| Earning seq. | 在重采样后的盈亏曲线上计算 Pearson 相关性 | similarity_threshold（实体: 0.8, 链接: 0.7） |

### Manipulation 检测参数

| 参数 | Round-trip | Same-direction |
|---|---|---|
| 目的 | 标记“买入-卖出”子序列：净持仓回到接近零，且收益可忽略，是洗盘信号 | 标记连续同向交易的延续段，可能反映协同建仓或协同出货 |
| max_time_diff | 120 分钟 | 10 分钟 |
| max_pos_diff | 100 tokens | 不使用 |
| max_earning | 1000 USD | 不使用 |
| min_seq_len | 不使用 | 5 笔交易 |
| max_diff_dir | 不使用 | 0（不允许任何反向交易） |
| entity_based | true | true |

实体检测和操纵检测之间的关系值得专门说明一句：当任意一条操纵规则把 entity_based 开关设为 true 时，同一实体内所有钱包的交易会先合并，再交给规则检测。这是“跨多个钱包的协同活动”从“单钱包视角不可见”变为“可被检测出来”的关键机制。在运行中的 ACT 示例里，三个头部持有者被合并成了一个实体，实体级别的 round-trip 检测随即在合并后的钱包上发现了跨钱包的洗盘窗口。

## 推荐工作流

使用 ManiScope 最高效的方式是遵循下面这个十步节奏。

1. 选一个有意思的时间快照。通常选取一段价格波动结束附近的时间最为有用，因为这样可以看到行情高潮时刻每个钱包的实际持仓状态。
2. 把 Top Holders Threshold 调整到能够覆盖你关心的人群规模。默认的 0.3 是一个不错的起点。
3. 点击 Update Snapshot，等待几秒钟让 Token Distribution View 渲染完毕。
4. 依次运行检测算法：先点击 Entity Detection 下方的橙色 Run Detection，再点击 Update Links 触发链接检测，最后点击 Manipulation Detection 下方的 Run Detection。
5. 在 Token Distribution View 上做一次整体扫视，估计红蓝描边的比例，并留意橙色虚线圆圈所标出的实体在哪里、有哪些相关持有者通过橙色虚线连回到这些实体。
6. 点击图中最大的红色描边节点。这通常对应着操纵量最大的钱包，从它入手能拿到最丰富的 Behavior Detail View。
7. 在 Behavior Detail View 中同时观察 actions、balance、earnings 三个维度的呈现，并打开 Show Manipulation Boxes 开关，让红色包围框叠加显示在动作小点之上。
8. 寻找 Behavior Detail View 时间线上的纵向对齐。如果多行钱包的小点都集中在同一时间段里，那么这些钱包之间存在协同行为。
9. 把这些时间窗口与右侧 Manipulation View 中的 K 线对照起来。K 线上的淡蓝色背景以及上下方的灰色统计柱告诉你哪些区间里操纵活动最密集。沿着卡片下方的淡蓝色连接带找到对应的蜡烛，问一句：价格对这次协同爆发是怎么响应的？是被拉升、被砸盘、还是只是被维持？
10. 把 K 线图上下的操纵事件卡片当作“跳转到有趣时刻”的快捷方式。每张卡片都是一次预先发现好的事件，可以直接拿去与价格图核对。

## UI 上看不出来的几点注意事项

ManiScope 有几个不那么直观的特性，最好提前知道。

页面在首次加载时会自动针对默认快照获取操纵检测结果，因此进入页面后可以立即使用，不需要先点任何按钮。但切换代币会清空缓存的操纵结果，每次切换之后必须再次运行检测算法。

实体检测器默认存在“欠聚类”问题。它把按小时粒度的余额相关性作为最严格的信号之一，因此那些由同一个操纵者控制、但充提币时间表不一致的钱包不会被聚到一起。补救方式是：在运行实体检测之后，主动点击任意一个被标记的成员节点，去阅读 Behavior Detail View 中的相关持有者行。剩下那部分网络通常会从这些行里浮现出来。降低链接检测的阈值还可以把更多关联拉到 Token Distribution View 的灰色连边层里。

Same Direction 检测同时包含单钱包的快速连续动作，并不仅仅是多钱包协同砸盘。一个钱包在 60 秒内连续买入 5 笔金额几乎相同的订单，与三个不同钱包在同一窗口内集体砸盘，会在底部卡片行里产生形态相似的卡片。这意味着像机械臂般运作的算法交易和真正的协同操纵都会出现在底部卡片中，因此不要简单地把“70 张同向卡片”理解为“70 个独立的协同小组”。

Manipulation View 上的淡蓝色连接带视觉上比较淡。但它是把卡片与某个具体时间区域唯一联系起来的视觉元素，值得花点时间训练眼睛去跟随它。

时间快照的选择比想象中更重要。在价格高点选取的快照与在缓慢下行阶段选取的快照得到的头部持有者群体并不相同，因为有些钱包在两个时间点之间退出了头部群体。如果想看清楚操纵高峰前后谁进谁出，就尝试几个不同的快照时间并加以对比。

仪表板目前没有展示钱包标签。底层数据中的 `simplified_owner_labels.json` 文件可以区分交易所钱包、合约钱包和普通用户钱包，但这些标签尚未在 UI 中暴露。能否区分某个“头部持有者”实际上是中心化交易所的充值地址，会显著改变对许多被标记事件的解读，因此把钱包标签接入 UI 是值得列为后续改进项的事情。

## 论文中描述但当前应用尚未实现的部分

论文在可视化分析系统之上还描述了一层 LLM 辅助的能力，目的是降低使用仪表板的人工成本。可视化分析这一半就是当前前端实际暴露出来的部分；LLM 辅助这一半属于未来路线图。供参考的是，论文一共列出了四类 LLM 驱动的能力：第一是 onboarding，由 LLM 引导用户熟悉系统、各个视图与视觉编码，并帮助用户基于单个视图或多个视图形成洞察；第二是自动洞察发现，由 LLM 探索数据并生成洞察，可以根据用户指令进行，也可以无指令地主动发现，从而减少重复性的人工探索；第三是洞察标注与定制化自动探索，用户可以基于个人偏好对洞察进行标注，系统再据此驱动后续的自动探索；第四是洞察汇总与报告生成，由 LLM 把最终的洞察组合成结构化的报告。这些功能目前都还没有接入运行中的前端，因此本手册只覆盖可视化分析这一表层。
